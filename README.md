# Family App

Семейное веб-приложение для ведения общей информации о членах семьи. Первый модуль приложения предназначен для хранения и обработки медицинских данных.

## Быстрый старт

Требуется актуальная LTS-версия Node.js и npm.

```bash
npm install
cp .env.example .env
npm run dev
```

Приложение запускается на `http://localhost:3000`. Шаблон `.env.example` содержит только пустые имена конфигурации; не добавляйте секреты в репозиторий.

## Стек интерфейса

Клиент работает на Nuxt 4 и Nuxt UI 4 с Tailwind CSS 4. Vue-слой размещён в каталоге `app/`; серверные Nitro-маршруты остаются в корневом `server/`. Общий shell обёрнут в `UApp`, страницы используют компоненты Nuxt UI и спокойную синюю тему с автоматическим светлым/тёмным режимом по системной настройке.

## Авторизация и семейные профили

Реализованы вход, выход, восстановление и сброс пароля через Supabase Auth, первоначальная настройка одной семьи, а также создание, просмотр, редактирование, архивация и восстановление профилей людей и их медицинских профилей. Для запуска этих сценариев заполните только `SUPABASE_URL`, `SUPABASE_ANON_KEY` и `APP_BASE_URL` в локальном `.env`; шаблон не содержит секретов. Ограничение частоты входа и восстановления настраивается в Supabase Auth как обязательное условие развёртывания.

Без локальных учётных данных доступны только credential-free проверки; реальная доставка email, PKCE callback, миграция и RLS требуют отдельного disposable Supabase-проекта и не считаются пройденными локально.

Единственный публичный маршрут bootstrap — `GET /api/v1/health`. Он не использует сессию или внешние сервисы и возвращает ровно:

```json
{ "data": { "status": "ok" } }
```

Ошибки API используют безопасный стабильный конверт `{ "error": { "code", "message", "requestId", "fields?" } }`; внутренние сведения в него не включаются. Клиент нормализует этот конверт и формы H3 `createError` через `app/utils/api-error.ts`, показывая пользователю только строковые ошибки полей и безопасные русские сообщения.

## Границы кода

```text
app/pages/, app/components/     Vue-представление и компоненты
app/layouts/, app/assets/       Shell, темы и клиентские стили
app/utils/                      Клиентские утилиты границы API
server/api/v1/                  HTTP-обработчики Nitro
application/                    DTO и прикладные сервисы
domain/                         Независимые предметные типы
ports/                          Интерфейсы репозиториев и хранилищ
infrastructure/                 Адаптеры провайдеров (Supabase)
```

Клиент обращается к семейным и медицинским данным только через `/api/v1`. Supabase применяется только в серверных адаптерах: SSR cookie-сессии Auth, семейная авторизация и PostgreSQL-миграции/RLS для семей, людей, медицинских профилей, событий, типов показателей и измерений. Браузер не обращается к Supabase Database или Storage напрямую.

## Реализованный объём и проверки

Миграция `supabase/migrations/0001_auth_family_people_profiles.sql` создаёт семьи, связь учётной записи с семьёй, людей и медицинские профили с RLS, политиками владения и ограниченными функциями первоначальной настройки и атомарного обновления профиля. Реализованы вход/выход, восстановление/сброс пароля, первая настройка семьи, профили людей и элементы аллергий, хронических состояний и предупреждений.

Миграция `supabase/migrations/0002_episodes.sql` создаёт эпизоды, симптомы и общие для семьи теги с RLS, политиками владения и ограниченной функцией `upsert_episode` для атомарного составного сохранения. Реализованы доменная модель, репозиторий, сервис и роуты `GET/POST/PATCH/PUT/DELETE` в `server/api/v1/people/[personId]/episodes/`: список с фильтрами, создание, просмотр, редактирование, завершение/повторное открытие и удаление. Валидация — Zod-схемы с переводом дат в UTC и инвариантом «дата завершения не ранее даты начала». Страница `app/pages/people/[personId]/episodes/index.vue` (список, фильтры, создание, пагинация) и детальная страница `app/pages/people/[personId]/episodes/[episodeId].vue` (просмотр, редактирование, завершение/повторное открытие с подтверждением, удаление) на русском языке, с состояниями загрузки/пустого списка/ошибки, подтверждением деструктивных действий и отображением дат в UTC.

Миграция `supabase/migrations/0003_medical_events.sql` создаёт таблицу `medical_events` (восемь типов событий, `source`, `author_id`, RLS по семье) и security-invoker функции `create_episode`/`complete_episode`: атомарно с созданием эпизода фиксируется событие `episode_start` (момент начала), а с переходом `active→completed` — `episode_end` (момент завершения); повторное открытие и ручное редактирование дат эпизода события не создают. Роуты `GET/POST` в `server/api/v1/people/[personId]/timeline` и `GET/PATCH/DELETE .../timeline/[eventId]`: список с `limit/offset`, фильтрами `from/to/type/episodeId`; создание доступно только для типа `note` (author — текущий пользователь), `PATCH/DELETE` — только для `note`, остальные типы — только просмотр. Страница `app/pages/people/[personId]/timeline.vue` (список, фильтры по типу, периоду и эпизоду, пагинация, редактирование/удаление заметок с подтверждением; создание заметки — через `POST` API и форму на странице эпизода) и секция связанных событий с формой заметки на странице эпизода, на русском языке, с состояниями загрузки/пустого списка/ошибки; даты отображаются в локальном часовом поясе.

Миграция `supabase/migrations/0004_measurement_types_and_values.sql` создаёт семейные типы показателей и измерения, шесть пресетов из спецификации, tenant-safe составные внешние ключи и RLS. RPC-функции `create_measurement`/`update_measurement`/`delete_measurement`, принадлежащие отдельной no-login роли без `BYPASSRLS`, атомарно синхронизируют измерение с событием хронологии типа `measurement`; прямые табличные мутации измерений запрещены, а `author_id` события вычисляется в PostgreSQL через `auth.uid()`. API предоставляет семейное управление типами через `/api/v1/measurements/types` и список/создание/редактирование/удаление измерений через `/api/v1/people/[personId]/measurements`. Поддерживаются числовые, текстовые, логические и составные значения, основные и дополнительные единицы, фильтрация по типу и периоду и необязательная связь с эпизодом; изображения и вложения остаются вне M003. Страница измерений включает адаптивную таблицу, динамическую форму, подтверждение удаления и управление пользовательскими типами; пресеты неизменяемы на уровнях UI, сервиса, репозитория и RLS.

Ограничение частоты для входа, восстановления и сброса обеспечивается Supabase Auth. Его настройка — обязательное условие развёртывания; приложение безопасно отображает provider 429 и не добавляет собственный limiter. Мутации семейных данных (профили, эпизоды, события, типы показателей и измерения) ограничены частотой на уровне Supabase PostgREST (настроенный при развёртывании), дополнительно защищены проверкой Origin, семейной авторизацией, RLS и строгими лимитами полей; отдельный app-level limiter не добавляется (риск-акцепт для M001–M003). `.env.example` содержит только пустые безопасные `SUPABASE_URL`, `SUPABASE_ANON_KEY` и `APP_BASE_URL`.

Интерфейс перенесён на структуру Nuxt 4 и компоненты Nuxt UI 4: общие layout/навигация, авторизация, профили, эпизоды, хронология, измерения и страницы-заглушки используют единые адаптивные формы, карточки, кнопки и статусы. Нативные `select` сохранены там, где необходимы доступные браузерные `option`; основные сценарии профиля, хронологии и измерений проверены при ширине 320 px, а светлая и тёмная темы — визуально.

Credential-free unit и Playwright-тесты используют синтетические данные и API interception. Текущий набор включает 22 файла/96 unit-тестов и 30 Playwright-сценариев. `tests/e2e/episodes.spec.ts` покрывает контракты эпизодов. `tests/e2e/timeline.spec.ts` и `tests/e2e/timeline-ui.spec.ts` покрывают API и браузерное отображение хронологии, включая measurement-события. `tests/e2e/measurements.spec.ts` проверяет Origin, строгую query/UUID/теловую валидацию и аутентификацию, а `tests/e2e/measurements-ui.spec.ts` — табличное отображение, динамическую форму, редактирование/удаление, управление типами и адаптивность 320 px. Выполнение миграций, RLS-проверки между двумя семьями, транзакционность «эпизод + событие» и «измерение + событие», доставка email, PKCE callback и браузерные сценарии с реальной учётной записью остаются явно pending до disposable Supabase-проекта и локальных credentials.

## Отложенный объём

Эпизоды, медицинские события, хронология, типы показателей и измерения реализованы. Импорт, файлы и изображения, остальные медицинские модули (анализы, посещения врачей и назначения, глобальный поиск), CI/CD и развёртывание не входят в этот срез.
