# Family App

Семейное веб-приложение для ведения общей информации о членах семьи. Первый модуль приложения предназначен для хранения и обработки медицинских данных.

## Быстрый старт

Требуется актуальная LTS-версия Node.js и npm.

```bash
npm install
cp .env.example .env
npm run dev
```

Приложение запускается на `http://localhost:3000`. Шаблон `.env.example` содержит только пустые имена конфигурации; не добавляйте секреты в репозиторий.

## Авторизация и семейные профили

Реализованы вход, выход, восстановление и сброс пароля через Supabase Auth, первоначальная настройка одной семьи, а также создание, просмотр, редактирование, архивация и восстановление профилей людей и их медицинских профилей. Для запуска этих сценариев заполните только `SUPABASE_URL`, `SUPABASE_ANON_KEY` и `APP_BASE_URL` в локальном `.env`; шаблон не содержит секретов. Ограничение частоты входа и восстановления настраивается в Supabase Auth как обязательное условие развёртывания.

Без локальных учётных данных доступны только credential-free проверки; реальная доставка email, PKCE callback, миграция и RLS требуют отдельного disposable Supabase-проекта и не считаются пройденными локально.

Единственный публичный маршрут bootstrap — `GET /api/v1/health`. Он не использует сессию или внешние сервисы и возвращает ровно:

```json
{ "data": { "status": "ok" } }
```

Ошибки API используют безопасный стабильный конверт `{ "error": { "code", "message", "requestId", "fields?" } }`; внутренние сведения в него не включаются.

## Границы кода

```text
pages/, components/, layouts/    Vue-представление
server/api/v1/                  HTTP-обработчики Nitro
application/                    DTO и прикладные сервисы
domain/                         Независимые предметные типы
ports/                          Интерфейсы репозиториев и хранилищ
infrastructure/                 Будущие адаптеры провайдеров
```

Клиент обращается к семейным и медицинским данным только через `/api/v1`. Supabase применяется только в серверных адаптерах: SSR cookie-сессии Auth, семейная авторизация и PostgreSQL-миграция/RLS для семей, людей и медицинских профилей. Браузер не обращается к Supabase Database или Storage напрямую.

## Реализованный объём и проверки

Миграция `supabase/migrations/0001_auth_family_people_profiles.sql` создаёт семьи, связь учётной записи с семьёй, людей и медицинские профили с RLS, политиками владения и ограниченными функциями первоначальной настройки и атомарного обновления профиля. Реализованы вход/выход, восстановление/сброс пароля, первая настройка семьи, профили людей и элементы аллергий, хронических состояний и предупреждений.

Ограничение частоты для входа, восстановления и сброса обеспечивается Supabase Auth. Его настройка — обязательное условие развёртывания; приложение безопасно отображает provider 429 и не добавляет собственный limiter. `.env.example` содержит только пустые безопасные `SUPABASE_URL`, `SUPABASE_ANON_KEY` и `APP_BASE_URL`.

Credential-free unit и Playwright-тесты используют синтетические данные и API interception. Выполнение миграции, RLS-проверки между двумя семьями, доставка email, PKCE callback и сценарии с реальной учётной записью остаются явно pending до disposable Supabase-проекта и локальных credentials.
